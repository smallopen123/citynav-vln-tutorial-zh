# 06｜从教学环境迁移到官方 CityNav

## 1. 复现分四层，不要直接从训练开始

```text
L0 数据可读 → L1 环境可运行 → L2 官方 checkpoint 可评测 → L3 自己训练可对齐
```

如果 L2 尚未成功，L3 的训练结果即使低也无法判断是模型、数据还是环境问题。

## 2. 获取官方代码

```bash
git clone https://github.com/water-cookie/citynav.git
cd citynav
git rev-parse HEAD   # 把 commit 写进实验记录
```

官方 README 当前给出的核心环境是 Python 3.10、PyTorch 2.2.2 和 CUDA 11.8。安装前先检查自己的驱动和 CUDA 兼容性，以官方仓库对应 commit 的说明为准。

## 3. 数据检查顺序

先验证这些内容，而不是一次性假设全部正确：

1. `cityrefer` 对象与描述 JSON 能否读取；
2. 四个 CityNav split 是否存在、条数是否合理；
3. RGB 与 depth 文件能否按 scene/block 对齐；
4. GSAM/检测分割结果是否与场景一致；
5. checkpoint 路径与配置是否匹配。

可以先在本教程目录运行：

```bash
python examples/inspect_citynav.py <citynav仓库>/data/citynav/citynav_train_seen.json
```

## 4. 官方基线入口

官方仓库提供 Seq2Seq、CMA、带 GSM 的目标预测/导航代码及预训练权重。入口名和参数可能随版本变化；当前公开说明中的 MGP 训练形式类似：

```bash
python main_goal_predictor.py \
  --mode train \
  --altitude 50 \
  --gsam_use_segmentation_mask \
  --gsam_box_threshold 0.20 \
  --learning_rate 0.0015 \
  --train_batch_size 12 \
  --train_trajectory_type mturk
```

不要盲目复制命令。先运行 `python main_goal_predictor.py --help`，再与当前 README、配置文件及 checkpoint 元数据核对。

## 5. 推荐的复现验收表

| 阶段 | 验收条件 | 不通过时优先检查 |
|---|---|---|
| 数据 | 能读取首条 instruction/target/path | 路径、版本、解压层级 |
| 渲染 | 固定位姿得到合理 RGB-D | 坐标系、相机参数、深度单位 |
| 单 episode | 动作推进且日志坐标合理 | heading 正负、米/格子、动作步长 |
| checkpoint | 官方模型能完整评测一个 split | 网络结构、权重键、预处理 |
| 指标 | 本地结果接近官方报告范围 | 阈值、STOP、split、随机种子 |
| 训练 | loss/奖励趋势合理 | batch、学习率、样本过滤、显存 |

## 6. 最小实验矩阵

不要一上来跑全部 unseen。建议：

1. 10 条 episode 做功能测试；
2. 一个小 split 检查日志和指标；
3. 官方 checkpoint 跑完整验证；
4. 去掉 GSM 做消融；
5. 恢复 GSM，再加入你的改动。

每次保存指令、真值目标、每步位姿、预测目标、动作、STOP 概率、最终 NE。SR 变化时才能追溯原因。

## 7. GPU 选择的现实建议

教学仓库不需要 GPU。官方评测/训练取决于模型和 batch：A5000 与 A100 都是 NVIDIA GPU，但 A100 通常有更强吞吐与更大显存配置；“可以运行”不等于相同 batch 和耗时。先按单卡小 batch 验证，再扩展多卡，并记录 GPU 型号、显存、GPU-hours、精度模式和有效 batch size。

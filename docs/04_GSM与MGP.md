# 04｜GSM 与 MGP：从一句话到可执行的地图目标

## 1. 先把四个名词拆开

### GNSS

全球导航卫星系统（Global Navigation Satellite System）。GPS 是 GNSS 的一个具体系统。它告诉无人机“我在全局坐标系的哪里”，但不会告诉它“哪个建筑是语言中的目标”。真实环境中还要考虑漂移、遮挡和坐标系转换。

### OSM

OpenStreetMap，一套开放地理数据。它可提供道路、建筑轮廓、类别和拓扑等信息。OSM 不是实时相机图像，语义标签也不一定完整或与三维场景完美对齐。

### GroundingDINO

开放词汇目标检测模型。给它图像和文本词语，例如“library”或“red-roof building”，它能返回候选边界框及分数。它把文字与当前视觉区域对齐，但边界框仍是图像坐标，需要结合深度、相机参数与位姿才能投影到世界坐标。

### GSM

在 CityNav 语境中可理解为 **Geographic Semantic Map（地理语义地图）**：把全局地理位置与目标/地标语义放进共同的二维地图表示，使模型能在目标尚未进入当前视野时，仍然进行大尺度目标推断。

## 2. GSM 是由语言直接生成的吗

不准确。语言会**查询和条件化** GSM，但 GSM 的底座主要来自地理数据、定位以及离线/在线视觉检测结果。概念流程是：

```text
GNSS/轨迹位姿 ─┐
OSM/建筑道路  ──┼─> 统一世界坐标 ─> 二维地理底图 ─┐
RGB + 文本类别 ─> GroundingDINO/分割 ─> 语义候选 ─┼─> GSM
CityRefer 对象/描述 ─────────────────────────────┘

语言指令 ─> 提取目标属性、地标、空间关系 ─> 在 GSM 上匹配/打分 ─> 预测地图目标
```

所以更准确的说法是：**GSM 预先组织环境知识；语言决定当前任务应关注地图中的哪些语义和区域。**

## 3. GSM 具体怎样表示

它不是一段自然语言，也不只是一个最终坐标。实现上通常把研究区域栅格化为二维网格，每个 cell 可以带有：

- 是否有建筑/道路等占据或地理类别；
- 某个语义目标出现在该处的分数；
- 与语言中目标属性或参照地标的匹配度；
- 到当前无人机位置的相对方向/距离；
- 探索或历史信息。

如果用张量表示，可把它想成 `H × W × C`：`H,W` 是地图格子，`C` 是地理与语义通道。模型最终输出的也可以是一张 `H × W` 的目标概率热图，再取峰值或局部极大值作为目标候选。

教学代码为了透明，没有构造图像张量，而用：

```python
gsm_landmarks = (
    ("市政厅", 0.0, 0.0),
    ("钟楼", 40.0, 45.0),
    ("图书馆", 80.0, 40.0),
)
```

它保留“语义实体 + 世界坐标”的核心关系，但省略真实检测分数、建筑轮廓、栅格特征和噪声。

## 4. MGP 做什么

MGP 可以理解为 map/metric goal predictor：输入语言、地图、当前状态和可能的历史，输出地图上的目标位置或目标分布。高层得到目标后，执行器才把它变为转向、前进、升降和 STOP。

```text
GSM 解决“环境里有什么、在哪里”
MGP 解决“这条指令这次指向哪里”
控制器解决“从当前位置怎样过去”
```

三者不能互相替代。

## 5. 为什么 GSM 会让 SR 提升很大

### 原因一：扩大有效视野

目标在几百米外时，当前 RGB 根本看不见。GSM 把全局候选带进模型，避免纯视觉策略在局部视野中盲搜。

### 原因二：把语言关系转为几何约束

“图书馆南侧”“道路另一边”在地图上可变成方向、距离和拓扑约束。候选从整座城市缩小到少数区域。

### 原因三：减少长轨迹误差累积

纯动作模仿每一步都可能偏一点；全局地图目标提供稳定锚点，让后续动作持续校正，而不是只延续上一步的误差。

### 原因四：帮助 unseen 泛化

结构化的地理关系通常比具体像素外观更可迁移。但如果 OSM 标签、坐标配准或检测结果有系统偏差，GSM 也会把错误放大。

## 6. 为什么 GSM 不能取代 RGB 和 Depth

GSM 是有误差的宏观先验；RGB-D 是在线证据。接近目标时，模型仍需：

- 用 RGB 验证颜色、外观和局部地标；
- 用 Depth 判断距离、建筑结构和可通行空间；
- 用连续观测发现地图—现实偏差；
- 避免到达错误候选并过早 STOP。

把最终目标坐标预测视为“导航已经完成”，相当于把地图 App 的终点标记当作车辆已经停进正确入口。

## 7. 建议的消融实验

为了判断提升到底来自哪里，至少比较：

| 设置 | 能回答的问题 |
|---|---|
| RGB-D only | 没有全局地图时的纯视觉上限 |
| OSM geometry only | 仅道路/建筑形状是否有帮助 |
| GSM without language score | 地图增益还是语言 grounding 增益 |
| GSM without visual validation | 在线 RGB-D 是否在纠错 |
| noisy GNSS/GSM | 方法对配准误差是否鲁棒 |
| oracle goal coordinate | 局部控制与 STOP 的能力上限 |

只有这样才能把“GSM 提升 SR”拆成可解释的因果链。

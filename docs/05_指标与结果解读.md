# 05｜NE、SR、OSR、SPL：结果表到底在说什么

设第 `i` 条 episode 的目标为 `g_i`，最终位置为 `p_i`，成功半径为 `r`。

## 1. NE：Navigation Error

```math
NE_i = \lVert p_i-g_i \rVert_2
```

它是最终位置到目标的距离，越小越好。平均 NE 容易被少量极端失败拉高，所以最好同时报告中位数和分布。

## 2. SR：Success Rate

```math
SR = \frac{1}{N}\sum_i \mathbb{1}[NE_i \le r]
```

SR 看的是**最终停止位置**。CityNav 常见成功阈值为 20 m，但你必须以当前评测脚本为准。模型若飞到目标附近却不 STOP、随后飞走，SR 仍为 0。

## 3. OSR：Oracle Success Rate

OSR 检查整条轨迹是否曾进入成功半径。若 OSR 明显高于 SR，说明模型“找得到，但停不好”或离开了正确候选；优先检查 STOP 策略、进度预测和历史一致性，而不是立即换更强视觉编码器。

## 4. SPL：Success weighted by Path Length

```math
SPL = \frac{1}{N}\sum_i S_i\frac{L_i}{\max(P_i,L_i)}
```

`S_i` 是是否成功，`L_i` 是参考最短/专家路径长度，`P_i` 是实际路径长度。失败项为 0；成功但绕远路也会被扣分。

## 5. 四个典型案例

| 行为 | NE | SR | OSR | SPL | 诊断 |
|---|---:|---:|---:|---:|---|
| 直达并正确停止 | 小 | 1 | 1 | 高 | 理想 |
| 到过目标后飞走 | 大 | 0 | 1 | 0 | STOP/进度错误 |
| 最终勉强进圈但绕很远 | 小 | 1 | 1 | 低 | 规划效率差 |
| 一直朝错误区域飞 | 大 | 0 | 0 | 0 | grounding/全局目标错误 |

## 6. 为什么不同论文的 SR 不能直接抄到一张表

在比较前逐项核对：

- 数据集版本与 split 是否相同；
- success radius 是否相同；
- 是原始轨迹还是修订/清洗后的轨迹；
- 是否允许额外 OSM、GNSS、检测器、闭源 MLLM；
- 相机高度、动作步长、最大步数是否一致；
- 单次还是多次采样，是否使用 oracle 选择；
- 训练数据、模型尺寸和 checkpoint 是否公开。

例如 CityNav 与 AirNav 即使都写 `SR`，环境规模、指令、动作接口、成功阈值和测试划分也可能不同。指标名字相同不等于任务难度相同。

# 01｜VLN 基础：模型不是“看一张图猜方向”

## 1. VLN 是什么

给智能体一句自然语言指令，例如：

> 从市政厅上空出发，经过钟楼，飞到图书馆南侧的红顶建筑并停止。

模型需要在一个此前未必见过的环境中，结合视觉观测和历史，产生一串动作并最终停在目标附近。这和三个相邻任务不同：

- **目标检测**只回答“图里哪里有目标”，不负责长距离移动。
- **路径规划**通常已知起点、终点和地图；VLN 的终点往往藏在语言里。
- **图像分类**是一次性预测；VLN 的动作会改变下一次输入，是闭环决策。

## 2. 五个核心对象

### Episode

一项完整导航任务。从起始位姿开始，到执行 `STOP`、成功、碰撞或超过最大步数结束。一个 episode 内包含多个 step。

### Step

一次“观测—决策—执行”。在第 `t` 步：

```text
o_t = 环境在当前位置返回的观测
a_t = policy(instruction, o_t, history)
o_(t+1) = environment.step(a_t)
```

### Observation

CityNav 类无人机 VLN 中，可能包括 RGB、深度、当前位姿/朝向、地图特征、已走轨迹和先前预测。不同论文开放给模型的信息并不完全相同，比较结果时必须核对。

### Action

动作空间可以是离散的，例如前进、左转、右转、上升、下降、停止；也可以输出连续速度或地图坐标。`STOP` 不是附属动作：飞到目标旁边却继续飞走，最终 SR 仍可能是 0。

### Policy

策略 `π` 把当前信息映射为动作：

```math
a_t = \pi(I, o_t, p_t, h_t)
```

`I` 是语言指令，`o_t` 是观测，`p_t` 是位姿，`h_t` 是历史。现代方法也可能先输出地图子目标 `g_t`，再由控制器转换成动作。

## 3. 为什么需要历史

单帧只能告诉模型“此刻看见什么”，无法完整回答：

- 刚才经过的是不是指令中的第二个地标？
- 已经向北飞了多远？
- 这个候选建筑是否之前被否定过？
- 是否已经进入目标区域，应该 STOP？

因此长期 VLN 的难点不是单纯识图，而是把语言进度、空间位置和视觉证据随时间累积起来。

## 4. 两种常见输出路线

### 端到端动作预测

模型直接输出 `FORWARD/LEFT/.../STOP`。优点是形式简单；缺点是长距离任务容易累积误差，且很难解释“模型认为目标在哪里”。

### 分层导航

高层先预测目标区域或地图坐标，低层负责向该目标移动和避障：

```text
语言 + 全局地图 → 宏观目标/子目标
宏观目标 + 当前 RGB-D → 局部动作
```

CityNav 的 GSM/MGP 思路可以放在这套框架下理解：GSM 提供地理语义先验，目标预测器把语言与地图实体对齐，执行过程仍需逐步更新。

## 5. 亲手做一次

运行：

```bash
python examples/run_toy_episode.py
```

然后把 `examples/toy_citynav.json` 中 `heading_deg` 从 `0` 改为 `180`。你会发现目标不变，但前几步从前进变为转向。这说明“知道目标坐标”和“产生正确动作序列”是两件事。

# 03｜一个 episode 如何运行：宏观导航不是只做一步

## 1. 先回答最关键的问题

一个 episode 有多个 step。**宏观信息不等于只在开头使用一次。**常见系统会在开头形成全局目标，并在后续 step 继续读取当前位置、视觉、历史和地图；可以每步重新预测，也可以每隔若干步或置信度降低时重规划。具体频率由论文实现决定。

CityNav 类闭环可以写成：

```python
observation = env.reset()
history = []
while not done:
    map_goal = goal_predictor(instruction, observation, history, gsm)
    action = local_controller(map_goal, observation.rgb, observation.depth)
    observation, done = env.step(action)
    history.append((observation, map_goal, action))
```

`map_goal` 不是环境直接给的答案，而是模型基于语言和当前证据产生的预测。

## 2. 两个连续 step 的具体例子

指令：**“从市政厅附近出发，飞到图书馆南侧 20 米的目标建筑并停止。”**

### Step 0：确定大方向

输入：

- 指令全文；
- 当前位姿 `(0, 0, 朝东)`；
- RGB 中看到市政厅和远处街区；
- Depth 表示前方空间可通行；
- GSM 中图书馆位于 `(80, 40)`。

推理：把“图书馆 + 南侧 20 米”落成候选地图目标 `(80, 20)`。由于当前朝东且目标在东偏北方向，低层先选择前进或轻微左转。

执行后，环境产生新位姿和新 RGB-D。注意：模型不是一次输出整条轨迹后闭眼执行。

### Step 1：用新证据纠正

输入仍包括同一句指令，但位姿、RGB-D 和历史已改变：

- 当前位姿可能变为 `(10, 0, 朝东)`；
- 新 RGB 中钟楼更清楚；
- Depth 发现正前方建筑轮廓变近；
- 历史记录已经走过 10 米。

模型可保持 `(80, 20)`，也可因新的视觉匹配把候选目标修正为附近坐标。局部控制器根据障碍和朝向决定继续前进、转向或调整高度。

这个过程一直持续，直到模型进入目标半径并发出 `STOP`，或达到最大步数。

## 3. 教学代码如何映射到这个闭环

运行：

```bash
python examples/run_toy_episode.py
```

对应关系如下：

| 教学代码 | 真实系统中的含义 |
|---|---|
| `Episode` | 一条导航任务 |
| `ToyCityNavEnv.observe()` | 相机/传感器/地图返回观测 |
| `GSMGreedyPolicy._ground_instruction()` | 语言—地图 grounding 的极简替身 |
| `GSMGreedyPolicy.act()` | 目标预测与局部策略的极简组合 |
| `env.step(action)` | 模拟器执行动作并产生下一帧 |
| `env.path` | 已执行轨迹/历史 |
| `STOP` | 主动结束并接受最终位置评测 |

教学策略知道 GSM 中的地标坐标，通过正则表达式解析“南侧 20 米”。真实模型面对更自由的语言、地图误差和视觉噪声，需要学习而非固定规则。

## 4. 亲手观察两个反例

### 坐标对，但执行仍会失败

把 `toy_citynav.json` 的 `max_steps` 改成 `3`。目标坐标没有错，但动作预算不足，episode 会在到达前结束。

### 经过目标，但最后失败

让策略到达目标后不执行 `STOP`，继续前进。此时轨迹可能曾进入成功半径，所以 OSR=1；最终位置离开目标，SR=0。这正是停止判断的重要性。

## 5. 宏观层与局部层的责任边界

```text
宏观层：目标是哪栋楼？大致位于哪里？下一段先去哪个区域？
局部层：当前朝哪转？前方是否被挡？飞多远/多高？现在该停吗？
```

研究中常见错误是只报告最终 SR，却不知道问题发生在哪一层。调试时至少记录每一步的预测地图目标、当前位置、动作、目标距离、可见地标和 STOP 概率。

# 07｜后续论文怎么读：先按“解决哪个瓶颈”分类

这章不把所有 aerial VLN 论文都说成 CityNav 方法。只有论文正文明确在 CityNav split 上实验，才能称为“直接使用 CityNav”；相关方法可能只解决相似问题或使用其他数据集。

## 1. 从原始 CityNav 出发的能力树

```text
CityNav 数据与 GSM/MGP 基线
├─ 推理与训练：怎样让 VLM 学会地图目标、CoT 和奖励？
├─ 课程学习：怎样从容易样本逐步训练到困难样本？
├─ 长期记忆：怎样避免数十/数百 step 后遗忘地标和进度？
├─ 分层控制：怎样分开粗目标、细动作和 STOP？
└─ 闭环纠错：不重新训练时，怎样生成—验证—修正？
```

## 2. 高相关工作对比读法

| 工作 | 首先关注的模块 | 阅读时追问 | 与 CityNav 的关系应如何核实 |
|---|---|---|---|
| CityNav / GSM + MGP | 数据、地图语义、目标预测 | GSM 输入究竟有哪些通道？ | 原始数据集与官方基线 |
| FlightGPT | VLM 的 SFT、GRPO、CoT 与奖励 | 训练样本为何分成 SFT 与 RL 子集？ | 查正文实验表的 dataset/split |
| SA-GCS | 语义难度估计与课程采样 | 提升来自样本顺序还是总训练量？ | 查数据章节与消融，不凭方法名判断 |
| HETT | 粗目标、细动作、历史/数据清洗 | 分层后哪个模块降低长轨迹误差？ | 查正式版本、代码与 CityNav 指标协议 |
| HTNav | 宏观规划与局部控制的混合框架 | 与 HETT 的层级、训练方式有何本质差别？ | 查 CVPR 正式论文和测试设置 |
| GeoNav | 全局地图 + 局部场景图 | 地理先验与视觉证据如何融合？ | 可能是相关任务，须看数据表 |
| SBFNav | 空间信念场、多候选、闭环更新 | 为什么分布优于一次性坐标？ | 确认是否直接报告 CityNav |
| ViSA | Set-of-Mark、视觉验证 | 结果是否受模型、prompt、采样次数影响？ | 确认是否同一 split 与额外 API |

表中的“工作”是研究路线索引，不代表全部已被同一顶会录用，也不代表全部使用 CityNav。引用前必须在论文首页、实验章节和官方 proceedings 三处核实。

## 3. 推荐阅读顺序

### 第一遍：只读任务与输入输出

每篇回答：用哪个数据集？输入哪些模态？输出动作、坐标还是文本？是否用额外地图/API？不要急着看网络结构。

### 第二遍：只读实验协议

记录 split、SR 阈值、基础模型、训练数据量、采样次数、硬件、是否公开代码。把不能对齐的结果标成“不可直接横比”。

### 第三遍：沿失败链读方法

```text
语言理解错
  → 地标 grounding 错
  → 地图目标错
  → 局部动作错/碰撞
  → 到达但 STOP 错
```

把每篇方法放到链上的一个或多个位置，才能看出它与自己研究问题是否匹配。

## 4. 面向 CityNav 的可复现研究题

### 题目 A：GSM 噪声鲁棒性

给 GNSS 坐标、检测框或 OSM 建筑位置注入不同强度噪声，绘制 SR/OSR/SPL 曲线。价值在于检验提升是否依赖近乎完美的地图配准。

### 题目 B：STOP 专项建模

对 OSR=1、SR=0 的样本训练进度/完成状态分类器。它比重做整个 VLM 更聚焦，也能直接对应指标缺口。

### 题目 C：多候选信念图

不立即把语言压缩成一个坐标，而是维护多个候选的概率，随着 RGB-D 新证据逐步更新。比较一次性坐标、Top-k 候选和完整热图。

### 题目 D：长期历史压缩

比较 Last-K、均匀采样、渐进间隔采样和结构化地标记忆。分别报告性能、上下文长度和推理时延。
